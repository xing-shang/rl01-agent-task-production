# 交包前内容复核

2026-10-03根据另组通用办公反馈及原题包抽查补充，适用于金融、医疗及后续领域。这是作者生产方法，不增加客户必交字段、评分门槛或运行要求。日常短prompt继续引用项目最新规则；具体复核放在项目背景及作者证据中。

从最终题面建立“要求→输入依据→Golden实际位置→RubricID”覆盖表。先列题面全部硬要求，再检查Rubric覆盖，不能从Rubric反推要求清单而漏掉未评分的条件。逐份打开最终导出的文件，核对业务用途、对象集合、公式、显示精度、筛选、冻结及题面其他要求。Golden满分仍可能漏题面要求；全部硬要求须实际满足，专业结论须独立回源。

审查全部Agent可见输入、技能、注释及元数据，检查待发现错误、待计算数值或Golden结论是否被提前提供。由风险分推导截止日等任务，输入已含答案字段时须明确其业务用途及被考察能力，不能仍把机械复制描述为推理。历史数据与当前任务窗口可以不同，须说明两者含义并核对时间与责任主体；不能仅凭间隔长就判业务不成立。刻意冲突或缺失必须有可执行的正确路径。

开放选择、排程或优化题，实际构造至少一个与Golden不同的合法方案并复核相关判据，记录方案、合法性依据和评分结果；不存在另一合法方案时，以约束或独立求解证据说明。人数、行数、受影响对象、统计及后续结论按候选方案和公开输入重新计算，不使用Golden特有常量。题面明确固定的文件名、字段、枚举及业务约束仍精确检查；未规定的表名、措辞、顺序和等价结构按内容判断。

针对高权重及关键失败点准备错误产物，确认评分能发现实质错误；用等价表达或有业务意义的部分正确产物检查误扣、全有全无和级联惩罚。不得执行未核验的第三方题包代码。能运行自己评分程序时保留实际回执；只有作者逐条评审能力时如实记录该方式，不能冒充外部Judge。按独立失败点原子化，不机械设置Gradient数量、条目分差占比或某权重数量上限。

逐条核对判据来源、必要性和可观察证据。Explicit回到题面，Implicit回到材料或必要业务含义。Judge无法看到的过程不能从产物无痕迹推断；源文件是否改动由环境保护或有证据的运行审计检查。隐式要求若无法公正判定，修复题面或评分，不用关键词、私有列名及except后统一返回零分掩盖读取失败；区分合法表达差异、无效产物和评分基础设施错误。

分别核对业务计算、显示精度及容差，Excel读取出整数不自动构成数值错误。原始JSON负项使用带符号负权重和negate=true；可执行TOML使用正权重和negate=true。按业务严重程度分配权重，复算扣分池及领域锚点；其他组个案建议不能覆盖当前合同的表示、固定模板或keywords结构。

输入逐份打开检查文字、图片、公章、页眉页脚及文档属性，按适用规则脱敏；医疗材料同时检查可能识别个人的标识及影像嵌入信息。核对实际路径、题面清单及目标环境可读性，最终ZIP解压后复验。不得为通用检查虚构统一最大目录层数或放宽已有文件名长度要求。

复核记录放入已有作者证据区，用现有Golden评审附件或可读摘要记录覆盖缺口、输入检查、替代正确方案、错误反例、Judge可见性及修复结果；无须为此新增客户必交文件或固定JSON字段。未完成、不可验证和不适用分别说明，不能只勾“已检查”。改变题面、输入或评分后更新版本并复核受影响证据。
