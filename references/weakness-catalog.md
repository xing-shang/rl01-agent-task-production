# W1—W14词表与构造边界

来源为用户20260928提供的26页构造方案第5—13页。原文明确`weakness_tag`取B列Weakness名称，W1—W14是A列编号。下表名称仅合并PDF换行，保留原义；未来若平台提供带编号枚举，以其正式映射为准。旧示例`W07-流程跳步`、`W12-约束遵循`与本表编号含义不一致，不可直接复制到新题。

2026-10-01的S09再次列出这个冲突，仍未答复；S02后文的示例也含相同旧标签，不能只把问题归于S03。当前继续按正文B列名称填写，正式枚举范围及带编号写法尚未由S09确认，详情见[冲突记录](conflicts-and-clarifications.md)。2026-10-02本地预检已补上本表14个B列名称的逐值核对，旧示例标签或自定义业务错误描述会报weakness-tag错误。此检查依据当前规范正文，不冒称平台枚举已获客户答复；题内触发对应仍须逐题人工核对。

| 编号 | B列名称 | 触发与应检查结果 |
| --- | --- | --- |
| W1 | 长文档下的硬约束遵循较差 | 长产物中内容、数量和真实文件结构约束同时存在；检查实际分页、页码域、公式、字数等，不以正文声称完成为据。 |
| W2 | 关键冲突下自行选边/修改输入，而不是模糊澄清或是说明具体冲突情况 | 同一关键事实跨来源冲突且改变结果；正确路径为依可用规则核实、澄清或具体说明冲突，不能擅改源文件。 |
| W3 | 阻塞状态的识别与恢复能力较差 | 关键资源或工具失败；考察合理重试、修复、备用路径和停止边界，避免无穷重试、过早放弃及伪完成。 |
| W4 | 多要求/多交付物下缺少Requirement Coverage Accounting | 多文件、sheet、章节或修改项；用完整交付范围核查遗漏，不依赖模型自述清单。 |
| W5 | 关键信息缺失时“该问不问” | 缺少决定性变量；提供可用澄清机制或允许的问题清单产物，不能静默猜值完成。 |
| W6 | 用户补充信息后只局部更新，没有Global Re-planning | 一个已给出的补充事实影响多个下游计算、排序、风险和建议；应全局传播，不只改文字。 |
| W7 | 长表格/多Sheet下的数据覆盖与抗干扰能力弱 | 多sheet、同名实体、跨期记录、状态筛选；正确结果依赖有依据的分组、过滤、去重和覆盖。 |
| W8 | 启动Subagent后把“已派发”当成“已完成” | 多个延迟子结果各持有必要信息；最终交付必须实际回收并整合，启动成功不能替代完成。 |
| W9 | Skill被形式化调用，但没有真正改变关键判断 | Skill特有SOP、阈值或冲突规则直接改变正确分支；只读技能或打勾仍会做错。 |
| W10 | 大Workspace下缺少Coverage Accounting，读了一部分材料就开始形成完整结论 | 必要证据分散在多文件簇或高密度材料中；核对要求与证据覆盖，不奖励无目的全读。 |
| W11 | 无据自造数据与口径 | 规范未给常用阈值、旧版口径混入；正确做法是回源、注明口径和不确定性，不能声称无依据数字来自指南。 |
| W12 | 跨源交叉核对缺失 | ≥3处来源的主体、分母、期间或有效口径不同；核对自算与登记值，回查规则后解释取舍。 |
| W13 | 规划与策略调整失当 | 多个真实交付要件与一条不可行原路径；应换策略并回查内容，不持续重试同一失败方法。 |
| W14 | 脱敏与合规疏漏 | 去除应匿名字段同时保留必要核验对照；检查最终文件及交付目录，避免未脱敏版混入和过度脱敏破坏证据。 |

逐题记录所选名称、实际触发位置、正确恢复/判断、对应可观察交付结果和Rubric。设计标签与正式轨迹是否复现分开记录；未实测不能写“已稳定复现”。一个任务可以覆盖多个weakness，每种在该题只计一次；1000条weakness专项的每种覆盖50—250条是整体项目要求，不能强加给用户的一小批金融题。

W8仅在真实Agent框架支持子代理时使用；模拟工具返回多个异步结果可属于依赖Workflow，但不能冒称已运行真正子代理。W2/W3/W5/W6的交互必须可回放。业务流程的正确最终状态可评分；rewardkit§3.4明确不额外添加“读了技能/调用次数/启动顺序”过程评分。触发和能力证明留在设计底稿与轨迹分析中。

安全与隐私类触发优先使用已获准的匿名化测试材料，不为构造W14引入真实秘密。来源、任务日期、单位、币种、脱敏映射和可接受假设应公开给被测模型至足以正确解题；答案、干扰身份与评测意图保留在私有底稿。
