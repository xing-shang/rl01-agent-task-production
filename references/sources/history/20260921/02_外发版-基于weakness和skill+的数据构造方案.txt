1.   项目背景与使用范围
●    本文件定义该RL从0到1标注生产下数据的规格、格式、质量标准与验收流程。
●    适用对象：提供标注数据的所有数据生产流程。
●    面向对象：供应商、内外部专家、标注质检平台。
●    写给领域专家：
     ○ 作为对应办公场景的专家，你熟悉该领域的任务要求，熟悉该领域办公目标实现的产
       物标准。
     ○ 你的工作是根据自己擅长的领域，选择合适难度的任务，给出能对应办公场景、具备
       真实业务价值的任务描述，并且给出恰当的参考文件，以及对应该任务的参考答案。
       同时你需要针对该任务，给出一套能衡量任务做得好坏的打分项。
     ○ 我们会根据你给的打分项
          ■① 对你提交的参考答案打分，看得分是否足够高（正确率>0.85）；
          ■② 用3个模型执行你给出的任务，并用你给出的打分项打分，看难度是否足够
           高。
     ○ 此外，人工质检会重点考察题目真实性、参考答案合理性、打分项设计合理性、是否
       hack等异常作弊情况，一经发现，直接打回。

基于skills/workflow的scaling的专项数据
1. 背景 & 出发点
                          5 / 14
目前 Cowork RL 数据中，大部分任务仍运行在相对简单的环境中：
●  以 filesystem / shell / 少量原生工具为主；
●  Tool schema、可用能力和调用方式相对固定；
●  Skill 即使存在，也经常只是辅助信息，并非完成任务所必需；
●  Workflow 多数是线性的「读取 → 处理 → 输出」，较少包含真实业务中的状态变化、异
   步依赖、异常恢复、跨工具协同等复杂过程。
下一阶段希望数据建设从单纯扩充 Task Distribution，进一步转向扩充 Environment
Distribution。




2.   整体数据目标
本专项主要覆盖以下几类能力：
Skill Dependency
任务必须真正依赖 Skill 中的特有信息、规则或 SOP 才能稳定完成。
skill能够包含一些特有信息或行为规则，避免 Skill 成为一个可有可无的 contextual
document




Workflow Execution
构造真实存在：多步骤依赖；多工具协同；branch；async；blocking state；subagent；的
长链路任务。（最好是有涉及subagent的，例如在codex下运行该任务会触发subagent）

MCP Scaling（低优）
扩大模型在非原生工具、陌生 Tool Schema 和不同 Tool 组合下的泛化能力。可主要通过
MCP

数据需要基于各 Agent Framework 可接入的 Plugin / MCP 能力构造任务，并在每条任务中
明确提供当前 Environment 下模型可使用的工具集合 / MCP。工具可以是框架已有能力，也
可以是动态注入的自定义工具（在题目里显式说明）。


                           6 / 14
3. Skills    数据需求
Skill Discovery
提供多个 Skill, 要求模型自行判断：是否需要 Skill，以及应该使用哪个 Skill。
Skill Dependency
构造：
 没有 Skill 中的特殊知识 / 行为规则，模型很难正确完成任务。
推荐构造方式
类型一：特殊业务规则
      明确规定：当两个 authoritative source 的关键字段冲突时，禁止自行选择，必须暂
  Skill
  停并向用户确认。
  Task 中主动埋入这种冲突。模型如果没有真正遵循 Skill：最终一定会进入错误
  branch。




类型二：环境特化 SOP
  例如 Skill 定义某企业内部审批流程： Draft → Compliance Review → Manager Approval
  → Publish ﻿

  Task    要求完成发布。如果模型直接： Draft → Publish 。最终 Workflow State 必须失
  败。

类型三：特殊计算 / 判定规则
    中包含：特殊阈值；内部映射规则；自定义字段定义；业务优先级；fallback 顺
  Skill
序。要求这些内容直接影响 final answer。


                                7 / 14
Skill Generation / Editing
可以增加一批：创建 Skill；修改已有 Skill；从 SOP 抽取 Skill；Skill migration；Skill
package repair之类的任务




4. Workflow      数据需求
Dependency-aware Workflow
任务中存在明确 dependency：
  A→B
  A→C
  B+C→D
  D → Final

要求模型：
●正确拆解 dependency；
●维护哪些任务已完成；
●避免提前执行依赖未满足的步骤；
●Final 前确认 dependency 已全部完成。




Subagent Workflow
构造必须依赖多个 Subagent Result 才能完成 Final 的任务。
