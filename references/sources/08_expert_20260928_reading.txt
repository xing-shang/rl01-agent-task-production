一、
你要做什么？
这项工作是用真实工作里的任务，来考察大模型（可以把它想成一个能力很强、但需要被考核的“实习生”）到底做得好不好。
你要做的，就是出一道来自你本行真实工作的题，并准备好下面这些东西交给平台：
题目描述：把任务讲清楚——什么场景、要它做什么、交付成什么样、有哪些硬性要求。
参考文件：完成这道题需要用到的真实文件（表格、报告、合同、政策文件等）。
参考答案：你自己（或你认可的高水平做法）把这道题做出来的一份标准结果，用来当“对照样板”。
打分文件：一张“该得分/该扣分”的清单，用来判断模型做得好不好。这一份平台会先用 AI 自动生成初稿，你来逐条核对和修改（后面详细说）。
一句话：你出题、给参考文件、给出标准答案，再把好评分这道关。
题目要来自“真有人会花钱请人做”的真实工作，不要为了刁难模型而编现实中没人会做的怪题。

三、
怎么判断难度、怎么把题出难
难度只看一件事：三个大模型做完这道题后的平均得分。 平均分越低，说明题越难、越有价值。
平台会用三个大模型各自把你的题做一遍，再用打分文件打分，取平均。
只要三个模型的平均分低于 70%，这道题的难度就算合格。 平均分再按下表归入 A1/A2/A3 三档，只影响这道题算在哪一档，不影响是否通过。
如果平均分到不了 70%（模型们做得太好），说明题太简单，需要加难或换参考文件重做。

你不用纠结“做这道题要花多少小时、要来回几轮”，这些暂时都不考察，把精力放在把题出得够难、够真实上。
把题出难的常用办法：
加真实约束和限制条件（指定口径、版本、格式、时间/预算限制等），逼模型放弃“标准套路答案”。
字数
让它在相互冲突的目标之间做取舍，而不是简单堆要求。
给的信息故意不完整，看它会不会主动提问、或先说清假设再做。
设计“看起来合理、其实有问题”的陷阱，看它能不能识别并否决。
要求跨多个文件、多个口径核对，不能只看一处就下结论。
要求它对不确定的地方主动标注、给出依据，而不是硬编一个答案。
提醒：加难度是要“真的更难”，不是堆到无解。堆到自相矛盾、根本做不出来，考的就变成“能不能识别做不了”，这是另一类题，出题时要想清楚自己到底想考什么。
四、
每一部分怎么准备
1.
自然语言描述任务场景、需要用到的材料、交付物要求。
包括任务说明，产出要求，硬约束（禁止项、文件名要求）必须用独立段落显式写出，不得隐藏在括号内。
用大白话把任务讲清楚，包含：什么场景、你是什么角色、要模型做什么、交付成什么文件、有哪些硬性要求。
硬性要求（比如“不许做什么”“文件名叫什么”“字数/单位/格式”）要单独一段写清楚，不要塞在括号里或藏在长句中间。
2.
该任务场景下真实的交付物是什么，就用什么源文件。
必须为真实数据；不得要求模型凭空猜测法规条款、政策口径、职责分工或统计数据。
数量没有限制，总大小在20GB以内。
就用这个真实场景里真会用到的文件，比如表格、PDF、报告、合同、政策文本。
必须是真实数据，不要让模型凭空猜法规条款、政策口径或统计数字。
涉及真实单位、个人的，先做匿名化/虚拟化处理，不要放真实涉密信息或身份证号、手机号这类敏感信息。
如果项目涉及的信息是公开且非盈利的、不涉及任何侵权问题的，则无需脱敏。

4.
打分文件——平台生成，你来改
三件套通过检查后，平台会用 AI 先生成一版打分文件，您基于该结果进行增删改留。
新产线的操作规范看【六、0917新版作业流程】；旧产线的操作规范看【七、0909旧版作业流程】。
打分项 = 一个得分点/扣分点，即考察交付物，
符合某一条在实际生产中被要求或有正向收益的打分项，则得分；
符合某一条实际生产中应该杜绝或避免的打分项，则扣分。
注意：不能在同一个打分角度上，既写得分点，又写失分点，造成双重得分或双重扣分。
每条打分项，描述一个具体的、可验证的评分标准，包含以下字段：
﻿任务描述description：具体的评判标准描述。
单条打分项要求
原子性：每条打分项描述一个独立、明确、可验证的评分点，仅检查一个方面（避免一条捆绑多个独立事实/多个可接受值）。
准确无歧义：表述完整、事实正确、依据可靠，使不同评分者能够形成一致理解。
可独立判断：打分项应包含作出判断所需的关键信息，不要求评分者额外推导、补充标准或进行二次判断。
不推荐：收入实现了明显增长。
推荐：收入同比增长了 65%。
来源合理：打分项必须来自以下内容，不能凭空增加“伪需求”：
项目描述中的明确要求；
参考文件中的明确要求；
根据任务目标和使用场景可以合理推导出的隐含要求。
有明确判定锚点：禁止使用“语言流畅”“结构清晰”“内容专业”等空洞描述，应明确说明可观察、可验证的表现。
不推荐：PPT 排版美观。
推荐：单页正文不超过 150 字，文本无明显遮挡、重叠或溢出。
客观可验证：优先评价能够直接核查的事实、数据、结构和结果，避免直接使用“美观”“深入”“专业”等主观词语。确需评价主观质量时，必须将其转化为具体的可观察标准。
粒度合理：既不要把多个独立要求合并为一项，也不要将一个完整动作拆成大量无实际意义的小项。
打分对象：如果你的输出文件有多个，在打分项中明确给出本条的打分对象。
负分项写法：应对负分打分不合预期
description 不要去写【如果 xxxx，扣多少分。】，而是直接写【xxx】，xxx 代表是的扣分的事件发生，比如“文中出现了诋毁某一国家领导人的言论”，不需要赘述扣分；
尽量少用/不用否定的句式，尤其双重、三重否定；
description 表述要清晰简洁，根据文件内容一步推理即可完成，不要二次推理；
不要写跨打分项的描述：比如在 R1 的描述里写“某一个角度由 R2 判定”等诸如此类。
打分项之间的要求
互不重复、互不冲突：不同打分项应评价不同内容，避免同一问题被重复计分，也不能出现判定标准相互矛盾的情况。
例如，“公文是否专业、有条理且合规”应拆分为：
文种选择是否正确；
格式要素是否齐全，如标题、主送机关、正文、落款、发文字号等；
请求事项是否明确，是否符合“一文一事”。
具有区分度：正分项和负分项的判定边界应明确；type为gradient项的，正分项要求能区分“部分满足”和“完全满足”，避免不同表现获得相同评价。
整体覆盖完整：所有打分项合起来应覆盖任务的主要目标和关键能力，并能够从不同维度评价交付物质量，不能遗漏关键要求。
权重体现重要性：同一份打分文件中，应根据各打分项对任务结果的影响程度设置不同的 weight，避免所有打分项机械地使用相同权重。
允许设置合理亮点项：可以评价项目要求之外、但基于常识会影响用户判断或交付质量的内容。此类要求应具有明确价值和合理依据，不能无限扩展任务范围。
判断结果稳定（鲁棒性）：同一套打分项由不同 Judge 或在不同时间多次评分时，结果应基本一致。若评分结果波动较大，应进一步明确描述、判定边界和示例。
主客观类型criterion_type：
Objective = 可度量、可验证，仅凭回答本身即可作出明确判定；
Subjective = 需要打分员的判断与语境解读（语气/质量/风格，或对某理由、断言、示例是否成立的判断）。
字段约束：criterion_type ∈ {Objective, Subjective}。
显隐式类型criterion_necessity：
Explicit = 在 prompt 中逐字明文给出的要求；
Implicit = 没有明说但从语境中必然推导出的要求。
字段约束：criterion_necessity ∈ {Explicit, Implicit}。
权重weight
分值（正分表示奖励，负分表示扣分/惩罚）。
不接受恶意负分、故意增加题目难度/降低分数的行为。
字段约束为weight ∈{+10、+7、+3、-3、-7、-10}，不能取任何其他值。

打分项分布要求
打分项的分值设计应符合统一标准，能够真实反映各能力的重要程度。主要包括：
领域锚点占比：交付物内容质量维度（交付物内容质量下所有二级标签）锚点正分，占全部正分的 30%以上，表示本题对专业性有很高的要求，非简单指令遵循就可满分，要求有极强的领域知识理解。
关键项占比：每题至少包含 2 条 Critically Important（+10）评分项，模拟用户真实期望，给出最影响产物本身可用性的打分点。
-10分项：仅用于重大专业错误、幻觉、业务安全、合规风险等真正影响答案可信度的情形，不得滥用。
一般来说，指令遵循、结论正确性、分析与论证质量与事实忠实性这些维度总是需要的。
对于行业性比较突出的交付物，应该覆盖专业规范维度。
对于ppt等设计类交付物，应该覆盖视觉美感与格式规范维度。
对于写作类交付物，应该覆盖结构与组织维度。
对于数学计算要求较高的交付物，比如金融场景，应该覆盖数值与计算准确性维度。

这道题什么时候算“过关”（平台会自动算）
三个模型的平均分低于 难度等级要求的正确率（难度够）：即A1介于60~70%、A2介于50~60%、A3<50%；
三个模型的得分至少有一个不为0。
你的参考答案得分不低于 0.85（标准答案和评分尺子对得上）。
三条都满足，才进入下一步。

h.
补充题目描述信息
根据题目实际情况，对题目关键信息进行选择或补充。
难度等级：易/简单-A1、中/中等-A2、难/困难-A3。按照评测出来的难度等级填写。A1 代表难度在 60%～70%；A2 代表难度在 50%～60%；A3 代表难度低于 50%。
评测的能力：这道题主要考察的能力，根据您的专业领域描述，比如文本组织能力、PPT 组织能力、信息搜素及整理能力等。
所属领域：在给出的领域中单选。
所属领域二级标签：在给出的选项中单选。
所属领域三级标签：从您的专业领域填写三级知识标签，短语描述清楚即可。
所属领域四级标签：从您的专业领域填写四级具体场景，简要概括其所属场景即可。
是否依赖 VL：即本任务是否需要模型具备从视觉信息提炼出文本信息的能力，类似看图描述出图中内容，从而才能作答正确。
任务说明：描述选择该任务的原因，重点强调真实性、实用性、工作中的核心收益、经济价值等。
所需工具：解决这个任务需要的工具，比如 code、ppt、excel、pdf、sql 分析等。
领域知识储备：解决这个问题需要的领域知识，尽可能写全面，您根据自己所在领域的具体知识填写即可。
专家耗时：您评估一个成熟专家完成该任务需要的时间。单位为小时。
i.
提交
上述流程结束后，提交出题。
七、返修次数上限
在专家提交出题后，会经过题目质检，如存在问题，会将题目返回给专家进行返修。质检通过后会进行最终确认和结算。
质检意见反馈时间：一周之内
返修次数上限：3次
专家返修3次后，题目仍存在得分问题或质量问题，则判定为不通过。
